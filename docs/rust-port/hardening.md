# Rust hardening gates

RUST-015 hardens the Rust port without declaring browser or MCP parity that has
not been implemented. The gates cover the deterministic boundaries that already
exist: daemon/MCP JSON frames, flow YAML, state headers and authenticated
payloads, URL policy, and cleaned HTML/selector boundaries.

## Fuzzing

The fuzz package is an isolated Cargo workspace at `fuzz/` with its own
committed `Cargo.lock`. `libfuzzer-sys` is exact-pinned (`=0.4.13`), and the
package is never a member of the production workspace. Targets are:

- `daemon_mcp_frames`
- `flow_yaml`
- `state_headers`
- `urls`
- `html_boundaries`

Run the bounded smoke with `scripts/fuzz_smoke.sh`. It copies each tracked seed
corpus to a temporary directory, runs the configured number of executions
(`FUZZ_RUNS`, default 64, maximum 4096), and checks the tracked seed digest before and after.
Do not pass `fuzz/corpus/*` directly to libFuzzer: libFuzzer may write new
interesting inputs there.

`scripts/fuzz_corpus_hashes.py --check` verifies
`fuzz/corpus/hashes.json`. Update the manifest only when deliberately changing a
seed, then review the seed and target together.

## Property tests

`symbrowse-core/tests/hardening_properties.rs` uses exact-pinned `proptest` for
bounded YAML totality, authenticated state round trips, state-name path safety,
allowlist label boundaries, and total IP classification. These tests exercise
pure code only and do not claim filesystem, subprocess, browser, DNS, or MCP
transport parity.

## Miri scope and explicit skips

Run `scripts/rust_miri.sh`. It invokes only the pure property target and the
pure daemon protocol unit tests. The following tests are intentionally excluded
from Miri because they require filesystem, process, socket, browser, or network
facilities:

- `symbrowse-core`: `config_contract`, `state_vectors`, `key_resolver`,
  `policy_guard`, journal store tests, profile discovery tests, state-store
  tests, and custom-pattern file tests.
- `symbrowse-daemon`: lifecycle/session registry tests and all server/client
  socket or autostart tests.
- `symbrowse-fetch`: HTTP/archive tests and cache/pipeline store tests.
- `symbrowse-mcp`: raw transport/proxy tests.
- `symbrowse-engine-chrome` and `symbrowse-engine-safari`: launch, attach,
  subprocess, socket, and real-browser tests.

Adding a new pure Miri target requires adding it explicitly to the script; no
broad `--workspace` invocation is used as a substitute.

## Dependency and unsafe inventory

`security/rust-hardening-inventory.json` is generated by
`scripts/rust_hardening_inventory.py`. It contains every resolved production
workspace dependency, owned-unsafe locations, the `deny(unsafe_code)` policy,
and the explicit status that transitive unsafe use still requires the
cargo-geiger run. CI runs:

```text
cargo audit
cargo audit --file fuzz/Cargo.lock
cargo deny check
cargo deny --manifest-path fuzz/Cargo.toml check
scripts/rust_geiger.sh
```

`scripts/rust_geiger.sh` runs the pinned cargo-geiger version against each real
crate manifest (the root manifest is virtual) and writes one JSON report per
production package under `target/hardening/geiger/`. The reports are CI
artifacts; they are not hand-written. An advisory or license failure is a
blocker; an unsafe dependency is accepted only when the report identifies its
transitive path and the entry is reviewed.
Owned `unsafe` is not accepted by this milestone.

## CI policy

`rust-ci.yml` is PR-fast for formatting, check, Clippy, tests, and the property
suite. Full dependency/security checks, Miri, and copied-corpus fuzz smoke run
on `main`, schedule, or manual dispatch. This keeps heavy maintenance tooling
out of required PR checks while retaining a comprehensive main-branch gate.

# RUST-010 file-guard contract

The fixture at `testdata/port/engine/file-guards.json` is generated by
`internal/engine/chrome/rust_fixture_test.go` through the pinned Go engine
implementation (`652453d1595fc302bd69c328e7da8a21dbee28b9`). Run
`scripts/rust-port/file_guard_fixture_gen.py --check` to verify provenance and
regeneration determinism.

## Uploads (SEC-003)

The Go oracle:

1. rejects an empty selector and an empty file list;
2. rejects an empty path, explicit `..` path segments, and uploads without an
   allowed directory;
3. resolves the candidate with `filepath.Abs` and `filepath.EvalSymlinks`,
   requires `os.Stat` to report a regular file, and compares the resolved file
   against each resolved allowed root with `filepath.Rel`;
4. accepts a file equal to an allowed root because the root/file equality case
   is accepted by `filepath.Rel`;
5. rejects a symlink whose resolved target leaves every allowed root; and
6. includes the supplied path in the missing, non-regular, and outside-root
   error messages. The Rust implementation preserves this observable error
   behavior; callers must not expose these errors to an untrusted client
   without applying their normal error-redaction policy.

All files are checked before the Chrome file-input command is sent. No upload
is possible when the effective allowed-directory list is empty.

## Downloads (SEC-004)

An empty or whitespace-only directory sends Chrome `behavior: "deny"` while
still enabling download events. A non-empty directory is made absolute,
created with `0700` for newly-created Unix directories, and sent as
`downloadPath` with `behavior: "allow"`. The current Go code does not
canonicalize the configured directory or reject a configured symlinked
ancestor.

Completed events carry the browser-reported `receivedBytes` value and a SHA-256
checksum only when the checksum is not already present. The checksum is read
from `<configured-download-directory>/<guid>`, not from the suggested filename.
If no directory has been recorded, the Go zero-value directory makes this a
relative `<guid>` lookup. Missing/unreadable checksum files produce an empty
checksum rather than an event error. Progress updates the most recent event
with the same GUID; unknown GUIDs are ignored. Event buffers retain the newest
500 entries per session.

### Deliberate SEC-004 contract correction

The planning matrix previously named collision handling, path ownership, and
integrity denial as if they were implemented by Go. They are not present in the
pinned implementation:

- suggested filenames are metadata only;
- existing suggested-filename files are neither rejected nor renamed;
- there is no collision reservation or overwrite check;
- there is no size-versus-filesystem-length check; and
- checksum failure is represented by an empty `sha256`, not a failed download.

The Rust port implements this measured oracle behavior and does not add a
stronger policy in this slice. A future collision/integrity hardening change
must update the Go oracle, fixture, matrix, and migration contract together.
